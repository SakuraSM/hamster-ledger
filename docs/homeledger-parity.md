## 兼容边界

- 个人本地账本及原有同步保留；共享、开放 API 与后台自动记账使用显式启用的联网账本，断网只读。
- 新数据使用 schema v2；升级前副本保留，旧客户端不能覆盖新数据。回滚使用升级前备份。
- 原币金额为该币种的最小单位整数；报表的 `amount` 仍为入账时折算的人民币分。参考汇率不代表银行实际结算价格，已入账的汇率快照不随行情刷新。
- Web 与 Android 均须验证。测试、构建、浏览器、模拟器、容器与真实模型分别记录，不能互相替代。
- 样本必须虚构。未配置真实模型时，识别联调记为未验证。

本文件随阶段验收更新，不把待实现项标记为可用。

浏览器使用隔离账号与虚构账单，实测两笔文本草稿、逐笔确认、凭证上传与原图查看。导出的归档包含 4 笔账单、1 个账户和 1 张凭证，恢复成新的本地账本后再次打开同一张 1254×1254 图片。图片使用仓库仓鼠素材，仅证明上传与恢复链路，不作为模型识别样本。截图见 `docs/evidence/homeledger-parity/attachment-preview.png`、`ai-mobile.png`。

Web 附件以 AES-GCM 密文存入 IndexedDB，数据密钥由现有密码保险库保护。加密前已保存的附件在启用密码后同样受保护；锁定时无法读取。Android 附件与索引在同一个 SQLCipher 事务中写入。服务端凭证存于持久化 SQLite，由账本角色控制访问。

归档是带 Base64 图片的 JSON 文件，不是 ZIP。每张图片最多 8 MiB，每次识别最多 5 张，每笔流水最多关联 10 张；服务端每个上传者目前最多使用 100 MiB，归档上限 160 MiB。服务端临时识别图片超过 24 小时自动清理；账本中的孤立附件由用户在备份工具中清理，回收站引用继续保留。

模型协议使用 OpenAI 兼容的 Chat Completions 文本和 `image_url` 数据 URL 输入，以及 `/models` 列表。参考：[图片输入文档](https://developers.openai.com/api/docs/guides/images-vision)、[Chat Completions 接口](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)。不绑定默认模型名；局域网 HTTP 必须显式开启，云元数据地址始终禁止，DNS 校验后固定请求地址。

服务器首次保存模型密钥时，在数据库同目录生成权限为 `0600` 的 `.model-key`。备份和恢复服务端时，须同时保留数据库及此文件；也可通过 `LEDGER_MODEL_MASTER_KEY` 提供 32 字节 Base64 密钥，并由部署者自行保管。密钥丢失后须重新配置模型。

真实模型识别仍未验证：当前没有提供真实服务地址、模型和可用凭据。Android 新界面和相机适配已通过类型检查，APK、模拟器与拍照在最终集成阶段验收。

- 原生界面创建专用令牌后 API 返回 200，隐藏并撤销后返回 401；创建、撤销均留下审计记录。
- 创建每月 15 元订阅并记录本期扣费，下次日期推进到 2026-11-03；为 500 元储蓄目标分配 500 元后，流水仍为 2 笔。授权系统通知后收到“储蓄目标已达成 / GoalQA”。
