# 能力与限制

| 能力       | 当前实现                                                         | 尚未实现或未验证                       |
| ---------- | ---------------------------------------------------------------- | -------------------------------------- |
| 导入       | UTF-8、GB18030 CSV；XLSX、XLS；表头与字段映射                    | PDF、图片、OCR；全银行格式覆盖         |
| 文件范围   | 人民币，Excel 单工作表；单文件 10 MB、15,000 行                  | 多币种、合并多工作表、超大文件流式解析 |
| 去重       | 文件 SHA-256；同源同流水号匹配；跨平台同额同账户候选             | 多候选自动决策、跨设备幂等同步         |
| 跨平台核对 | 银行与支付平台、相同账户与金额、两天时间窗口；人工关联或保留两笔 | 匹配准确率尚未以真实大样本评估         |
| 分类       | 关键词与用户商户规则                                             | 未调用大模型，未提供机器学习训练       |
| 汇总       | 已确认记录、退款抵扣支出，转账与还款不计收支                     | 退款自动关联原消费、投资损益与会计报表 |
| 图表       | 支出趋势及分类原额                                               | 图表分类金额未按退款重新分摊           |
| 保存       | Web localStorage；版本化模型；异步平台接口                       | 加密存储、账号、云同步、多进程并发控制 |
| 备份       | CSV 与完整 JSON 导出                                             | JSON 恢复与增量迁移                    |
| 撤销       | 当前会话最后一次修改                                             | 刷新后操作历史                         |
| App        | 可构建的共享业务包和平台协议                                     | 原生工程、安装包、商店发布与设备验证   |

`apps/web/public/samples` 的三份 CSV 合计 9 条虚拟交易。支付宝与招行的 36 元消费关联后，净支出为 268.80 元、收入为 18,500.00 元；28 元退款抵扣支出，500 元充值和 2,000 元还款不计收支。

更多输入边界由 `tests/ledger.test.ts` 覆盖。测试通过只说明已列出的行为满足断言，不等于全部账单格式、平台和输入都已验证。
