# Android 支付消息记账

支付消息记账位于「更多 → 支付消息记账」，默认关闭。首版从支付宝、微信的明确支付通知生成本机候选；用户在前台核对并确认后，才通过现有账本控制器保存交易。它不直接读取支付账户或短信，也不保证覆盖全部支付场景。

## 开启与核对

1. 选择支付宝、微信支付来源，绑定一个未归档、未连接云端的本机账本，保存采集设置。
2. 打开系统「通知使用权」设置，授权仓鼠记账。普通发送通知权限不能读取其他应用通知。
3. 收到新支付通知后，在待确认列表打开完整编辑器，核对类型、实付金额、商户、时间及分类，手动选择实际收付款账户。
4. 确认保存，或将疑似重复消息关联已有账单；不需要记账的消息可忽略。

设置的开关和来源在点击「保存采集设置」后生效。关闭后立即停止采集。重新开启、切换来源或绑定账本，会以保存时刻作为新的采集起点，不补采此前通知。事件固定归属采集时绑定的账本；切换当前账本不会改变归属，核对前会先切换至绑定账本。

解析器仅识别人民币模板。优惠金额、余额、银行卡尾号不会当作交易金额；无法确定的字段留空或提示核对。复杂交易使用完整编辑器校验，支付渠道不会被自动当作资金账户。锁屏隐藏正文、通知合并、厂商省电策略及模板变化均可能导致漏记。

## 重复与保存失败

同一通知的重复回调与系统重新连接使用稳定事件标识，避免重复候选。同金额的不同交易仍独立保留。疑似重复可人工关联已有记录；明确相同来源、订单号的普通账单不能再次入账。

保存串行执行。账本保存失败时，候选及表单保留；账本已保存但消息状态回写失败时，界面识别稳定账单标识，只允许恢复状态或关联已有记录，不再次增加金额。已删除的确认账单不会因旧候选而自动复活。

## 本机存储与隐私

原账本继续使用 SQLCipher。通知收件箱独立保存在应用私有 `noBackupFilesDir` 中，配置和消息正文使用 Android Keystore 密钥及 AES-GCM 加密，事件标识使用独立 Keystore HMAC 密钥。系统允许的来源、当前 Android 用户和支付模板共同限制采集范围；聊天、营销、验证码、群组摘要及本应用通知不保存。

默认保留七天、最多 500 条待处理消息。过期数据在访问或采集时清理；容量满会拒绝新事件并显示错误，不覆盖旧消息。密文损坏或密钥丢失会明确报错，不生成新密钥来覆盖原数据。确认或忽略后移除正文，短期保留去重标识；清空收件箱同时推进采集起点，系统重连不会重新导入清空前的通知。

未确认消息不进入账本 JSON、导出、备份或同步，没有服务端通知接口。确认后的账单仅使用现有来源与去重字段，不保存完整通知正文。确认交易以后按普通账单规则参与用户主动执行的备份和同步。

## 开发验证

```sh
npm run check
ANDROID_SERIAL=emulator-5582 npm run android:test-inbox
ANDROID_SERIAL=emulator-5582 npm run android:qa-publishers
npm run android:apk
```

测试脚本仅接受 Android 模拟器。通知发布器使用专用测试版本的微信、支付宝包名，仅在对应真实应用不存在时安装，用合成消息验证系统监听链路；它们不访问支付服务。原生存储测试使用独立测试包与密钥，不修改主应用账本。

本次通过 289 项项目测试、3 项 Kotlin 单元测试、6 项 Android 仪器测试，并完成 API 36 ARM64 模拟器交互验证。记录见 [验证报告](evidence/payment-inbox-2026-10-12/verification.json)。模拟器的系统通知链路验证不代表真实支付模板覆盖率。OPPO 已断开，真实微信／支付宝正文、锁屏、厂商后台限制和设备重启后的表现仍待真机验收。
