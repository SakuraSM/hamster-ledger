# 鲨鱼记账能力对齐

本次实现以公开列出的日常记账能力为范围，保留仓鼠记账已有的账单导入、跨平台核对和资产账户能力。Web 能力已实现；原生系统小组件和关闭网页后的系统提醒仍未对齐，不能把 PWA 快捷入口视为原生小组件。

## 依据

核查日期为 2026-10-02。依据为 [鲨鱼记账官网](https://www.shayujizhang.com/)、[鲨鱼记账 App Store 页面](https://apps.apple.com/cn/app/id1079718756) 和 [鲨鱼记账 Pro App Store 页面](https://apps.apple.com/cn/app/id1163515895)。这是公开功能清单对齐，未反编译、复制原 App 代码或使用真实用户账单；“3 秒记账”等操作耗时未进行等价性测量。

## 同步行为

同步按完整账本进行。没有本机修改时获取远端更新；只有本机修改时携带已知 revision 上传。双方都修改时停止自动同步，保留原本机数据，并提供云端版本预览及“恢复为新账本并同步”。不执行记录级自动合并。

本机解锁密码保护当前浏览器存储。云端账号由自托管服务管理，数据保存在 SQLite。JSON/Excel 导出和云端数据库为明文。注册账号后须由用户选择要连接的账本，未连接的账本不会自动上传。

## 验证范围

测试数据均为虚构。使用 Node.js 22，浏览器以独立测试 Origin 运行，保留原预览地址的账本。

- `npm run check` 通过：86 项 Vitest 测试、4 项 Sites 打包测试、4 项服务端测试，连同格式、设计变量、类型、ESLint、共享包边界和生产构建。Web 与 core 另通过 deterministic-frontend 静态门禁。
- 服务端测试覆盖用户隔离、登录退出、Origin 校验、无效账本拒绝、过期 revision 和同一 revision 并发写入。
- 浏览器覆盖新增/编辑/删除/恢复、预算、日历、周期补记、标签检索、主题与金额隐藏、JSON/Excel 导出恢复、云端自动同步和冲突保留、本机加密解锁。
- Docker 镜像构建、注册、写入账本及重启后读取相同数据通过。
- Chromium 1440×1000 桌面与 390×844 手机视口验证；最终报表页面 axe WCAG A/AA 检查无违规，深色总览与设置页也无违规。手机报表没有横向溢出。生产预览重新加载后无应用错误日志。
- 关闭测试服务器后，从缓存重新打开并解锁，新增账单成功；服务恢复后自动补同步，已在云端读到该条记录。每日前台提醒也已在浏览器触发。
- 原预览 Origin 升级前后的账本存储摘要一致。测试使用独立端口与 SQLite 文件，没有重置原账本。
- 上述证据不能替代所有浏览器、原生系统或真实业务数据验收。

原生工程继续遵循 [App 开发准备](mobile-readiness.md)，不引入占位 App。自托管启动、Origin 和数据库备份见 [部署说明](self-hosting.md)。

## 交易一致性修复

2026-10-02 的 CR 发现 5 项问题，已完成修复。修复前新增回归用例有 11 项失败，修复后通过，并补充了并发、非法日期与旧数据兼容用例。

| 问题                       | 修复结果                                                           | 验证                                                                                                         |
| -------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| 加密迁移丢失并发写入       | 同源写锁保护迁移与保存；源明文变化时中止，原数据保留               | 两个浏览器标签页实测一方持锁、另一方排队；旧页面保存被明确拒绝，原账单保留。未遵守写锁的写入由源快照核对拦截 |
| 旧编辑表单覆盖远端金额     | 保存时比对原账单快照；冲突后保留草稿，可显式加载最新账单           | 远端从 100 元改为 200 元，本机只改备注会被拦截；加载最新后保存仍为 200 元                                    |
| 错误日期备份导致白屏       | 账单、账户校准、周期规则和账期使用有效日期校验；服务端复用同一模型 | 浏览器拒绝错误日期备份且页面可继续操作；无效 API 写入不改变账本或 revision                                   |
| 分类改名后新账单仍用旧名称 | 默认分类跟随稳定分类 ID，归档后从有效分类中选择                    | “餐饮”改为“吃饭”后新账单默认“吃饭”，200 元已有支出加 42 元后预算已用 242 元                                  |
| 链式重复流水删除不完整     | 删除、恢复与待核对检查覆盖整个关联组；后续导入指向最终主记录       | 兼容 A←B←C 旧链，删除后支出为 0，恢复后仅计主账单 100 元                                                     |
