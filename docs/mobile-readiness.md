# 后续 App 开发准备

当前可复用的是业务包、存储协议和设计变量。仓库还没有 iOS、Android、HarmonyOS 安装包，也没有原生设备验证。

## 已准备的边界

| 能力     | 可复用内容                             | App 仍需实现                               |
| -------- | -------------------------------------- | ------------------------------------------ |
| 账务计算 | 整数分金额、模型校验、收支汇总         | 原生展示和可访问性                         |
| 重复核对 | 去重与关联规则、原始记录模型           | 触控核对界面                               |
| 文件导入 | 平台无关的表头与行解析                 | 文件选择、沙箱权限、编码、Excel 解码及哈希 |
| 存储     | 异步 KeyValueStore 与 LedgerRepository | SQLite 或原生存储适配、备份恢复与迁移      |
| 视觉     | JSON 设计变量、仓鼠 PNG 标志           | 原生组件、字体与图表                       |

## 首个 App 切片

1. 明确目标平台和离线数据保护要求，再记录技术选型。
2. 在 `apps/mobile` 建立真实工程，接入现有 workspace 包。
3. 先运行虚拟账本，证明汇总和去重结果与 Web 一致。
4. 实现原生存储适配并通过 `tests/repository.test.ts` 所表达的读写、隔离和失败契约。
5. 打通一个平台的 CSV 文件选择与导入，再加入核对页面。
6. 增加迁移、导出恢复、前后台切换、大文件内存测试和设备验证。

保留 TypeScript 业务包后，React Native 或 Expo 可以直接复用业务代码；采用其他语言的原生客户端时，需要另外定义数据交换边界。当前不提前选择框架，也不生成无法运行的空壳 App。

## 原生开发前必须明确

- SQLite 存储结构、账本版本迁移与回滚。
- 密钥存储、备份加密和设备共享时的访问策略。
- App 退出、文件权限撤销及存储写入失败的恢复行为。
- 是否需要多设备同步，以及如何识别重复操作和处理冲突。
- 大文件解析放入工作线程或原生任务时的取消与进度协议。

这些条目是待完成的产品与实现决策，不能据此声称当前 App 已具备对应能力。
