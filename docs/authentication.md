# 登录与认证策略

首次进入显示登录页，也可选择“仅在本机使用”。登录控制云端同步，不代替本机账本的加密解锁。退出账号不会删除本机账本。

## 账号与密码

账号支持 3–64 位字母、数字及 `. _ @ -`，登录时统一转为小写。新注册和改密要求 15–256 个字符，支持空格与 Unicode；拒绝少量常见口令和重复字符。没有联网查询泄漏口令库。

密码采用随机盐和 scrypt 摘要，参数为 `N=131072, r=8, p=1`，参考 [OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。每个服务进程最多同时执行 2 个密码派生任务。旧账号按原参数验证，成功登录后升级摘要；已有密码不因新的长度要求而失效。

## 会话与请求保护

| 控制     | 当前行为                                                             |
| -------- | -------------------------------------------------------------------- |
| 默认登录 | 浏览器会话 Cookie；绝对有效期 12 小时，闲置 30 分钟失效              |
| 记住登录 | 用户主动勾选后持久保存；绝对有效期 30 天，闲置 7 天失效              |
| 活动续期 | 用户操作与受保护的写请求更新活动时间；后台 GET 检查不续期            |
| 会话轮换 | 登录替换当前客户端旧会话；每个账号最多保留 5 个会话                  |
| 修改密码 | 校验当前密码，撤销所有旧会话，并为当前客户端签发新会话               |
| 设备管理 | 可查看自己的会话；退出其他设备需要再次验证当前密码                   |
| Cookie   | `HttpOnly`、`SameSite=Strict`；HTTPS 使用 `Secure` 和 `__Host-` 名称 |
| 会话存储 | 服务端保存会话令牌摘要；前端不把密码或会话令牌写入 LocalStorage      |
| 写请求   | 校验 Origin、客户端请求头、会话 CSRF 令牌和预期账号 ID               |
| 登录错误 | 不存在的账号和错误密码使用相同错误提示                               |
| 请求边界 | 认证 JSON 上限 8 KiB；账本请求上限 20 MiB；限制请求超时与请求头数量  |

客户端对过期会话暂停同步并提示重新登录，本机记账仍可继续。Web CSRF 令牌只保存在页面内存中。登录跳转仅保留已支持的站内目标。

## Android 原生会话

原生客户端使用 `/api/native/auth/*` 与 `/api/native/books`。登录和改密仅返回该通道专用的 Bearer 令牌，不设置 Cookie。数据库记录会话所属通道；Cookie 与 Bearer 凭据不能互换。原生通道拒绝带 Origin 或 Cookie 的请求，受保护写入仍校验 CSRF 和预期用户 ID。原有浏览器来源校验保持不变。

未勾选「记住登录」时，Android 凭据只在进程内存中保存；勾选后通过 SecureStore 保存在设备 Keystore 保护的存储中。密码不落盘。服务地址与账本放在加密数据库中，凭据绑定服务 Origin 和账号；失效后停止同步，本机记账可继续。正式构建只接受 HTTPS，开发构建额外允许本机调试地址。

## 限流

每个账号在 15 分钟窗口内最多执行 10 次认证尝试，成功后重置账号计数；IP 限额为 15 分钟 40 次，注册额外限制为每小时 5 次。限流计数保存在 SQLite，重启不会清空有效窗口。拒绝请求返回 `429` 和 `Retry-After`，页面显示重试倒计时。

IP 键来自服务器连接地址，不读取客户端提供的转发头。反向代理部署时需要考虑共享额度。当前没有分布式限流或 CAPTCHA。

## 管理员重置密码

本版本没有邮件自助找回。管理员可在受信任的服务器终端运行：

```sh
npm run auth:reset -- --username account-name
```

命令使用与服务相同的 `DATABASE_PATH`，生成一次性展示的临时密码，撤销该账号的所有会话，并清除账号的限流计数。账号持有人使用临时密码登录后，必须先设置新密码，才能访问云端账本。不要把终端输出粘贴到公开日志或 Issue。

## 升级兼容

前端构建和后端进程需要一起更新。数据库启动迁移保留用户、密码摘要和账本，但会撤销缺少新会话字段的旧会话，升级后需要重新登录。新前端遇到旧登录协议时会拒绝启用同步，仍允许仅在本机使用。

对外部署必须配置准确的 HTTPS `PUBLIC_ORIGIN`。HTTP 仅允许本机地址。服务端提供 HSTS、禁止被嵌入、CSP 和权限策略响应头。服务器数据库仍是明文账本，不提供端到端加密、MFA 或 SSO。

## 验证范围

本轮 `npm run check` 通过 114 项 Vitest、4 项 Sites 和 20 项服务端测试，共 138 项。认证测试包括旧账号迁移、CSRF、过期与轮换、改密撤销、会话所有权、管理员重置、注册关闭、请求大小、登录状态竞争，以及原生与浏览器会话隔离。

实际浏览器验证了桌面与手机登录页、错误密码、注册、仅本机入口、改密及退出；Web 改密后，安卓旧会话失效且本机账单保留。登录页 axe A/AA 检查通过。原生端另验证了注册、记住登录、上传、同步与冲突恢复。

管理员临时密码的强制修改、单设备手动撤销主要由自动化测试覆盖。真实公网 TLS、反向代理、多实例与负载未在本次验收中覆盖；自动化测试不代表完整的生产安全审计。详细运行记录见 [现代组件与 Android 验证](design/modern-ui-android-qa.md)。
