# 现代组件与 Android 验证

验证日期：2026-10-03。账号、金额、文件和截图均使用合成数据。Web 使用独立测试来源；原有本机账本在刷新前后另做内容摘要比对。

## Web 组件与交互

输入、密码、按钮、选择、日期、复选框、弹窗及通知使用 Mantine。`Choice` 将既有选项描述转成库的下拉数据，浏览器中渲染的是可搜索选择器。页面结构、仓鼠标志及暖色主题保留。

| 场景           | 运行结果                                                               |
| -------------- | ---------------------------------------------------------------------- |
| 记账与分类搜索 | 实际下拉选项及键盘可选择分类；金额保存为整数分                         |
| 日期和时间     | 手机使用日期弹窗；日期与小时调整正确回填                               |
| 嵌套弹窗       | Escape 先关闭日期，再关闭记账；焦点返回「记一笔」；有回归测试          |
| 减少动态效果   | 模拟 reduced-motion 后，弹窗计算过渡时间为 `0s`                        |
| 手机排版       | 390 × 844 下无水平溢出；输入、日历和登录页可操作                       |
| 文件与资产     | CSV 识别 4 条并完成导入；新增 1,000 元资产成功                         |
| 夜间主题       | 输入、日期和文件占位文字可读；已修正日历与占位文字对比度               |
| 登录           | 桌面和手机登录页 axe A/AA 无违规；实际错误密码、登录、改密、退出已验证 |
| 跨端会话       | Web 改密后撤销 Android 原会话；安卓提示重新登录，本机账单保留          |

记账/日期弹窗、导入完成、资产与登录页执行了 axe 的 WCAG 2 A/AA、2.1 AA 检查，运行检查前等待过渡结束。自动检查不等于完整读屏器验收。

## Android 运行证据

使用单独创建的 Android 16 / API 36 arm64 模拟器，未操作其他项目的模拟器。构建包含 SQLCipher，未用 Expo Go 代替原生构建。

| 场景       | 运行结果                                                                         |
| ---------- | -------------------------------------------------------------------------------- |
| 首次进入   | 原生登录/注册与「仅在本机使用」入口可用                                          |
| 保存与重启 | 42.35 元记录保存后强制关闭、重开仍在；后续编辑为 45.67 元成功                    |
| 资产关联   | 1,000 元账户关联 12.34 元支出后，余额 987.66 元                                  |
| 回收站     | 该支出移入回收站后可恢复；关联数据保留                                           |
| 预算       | 总预算 100 元，对应本期已用 58.01 元、剩余 41.99 元                              |
| CSV        | 系统选择器读取虚拟支付宝账单，预览并导入 4 条                                    |
| Excel      | 包含 Excel 日期单元格的相同流水识别为 4 条重复，不再次计入收支；原始重复记录保留 |
| JSON       | 系统分享打开；导出读回含 5 条记录；选择该 JSON 后恢复为新账本                    |
| 注册与同步 | 注册合成账号、上传、修改并同步至版本 2                                           |
| 冲突       | Web 更新至版本 3、本机另有修改时提示冲突；预览恢复为新账本，原账本保留           |
| 凭据撤销   | Web 改密后 Android 凭据失效，云端操作停止，本机仍可记账                          |
| 数据库     | 启动要求 `cipher_version` 存在；数据库非明文 SQLite 文件头；失败队列测试保留原值 |
| 键盘与提示 | 收起键盘保留草稿；保存提示移到导航栏上方，底部按钮仍可点击                       |

系统分享只打开选择界面，没有向邮箱或云盘发送文件。通知、周期规则、分类、日历及报表已实现；业务规则由共享测试覆盖。页面存在或类型检查不等于通知实际送达、所有机型或大数据量验收。

GB18030 使用同一个合成文件做了修复前后对比：旧 APK 无法识别表头、有效记录为 0；新 APK 正确识别 4 条，保留中文商户名称。四字节字符另有独立编码字节的回归测试。从示例账本进入导入时，先切换到「我的账本」，演示与真实账单分开。

## 构建与自动检查

执行入口：`npm run check`、两端 DFA 静态门禁、`expo install --check`、`npm run android:export` 和 `npm run android:apk`。自动化检查与模拟器操作证据分别记录，不互相替代。

已完成内置 JavaScript 的 APK 构建与覆盖安装，停止 Metro 后能独立启动；原 987.66 元资产余额保留。新增 0.01 元本机记录并强制重启后，本期 58.02 元及记录仍存在。横屏显示正常，可滚动查看页面。重复核对由 6 组减少为 5 组，撤销后恢复。

当前全量检查通过 114 项 Vitest、4 项 Sites 和 20 项服务端测试，共 138 项。原生编码验证还包括 UTF-8 BOM、GB18030 四字节字符及损坏编码拒绝。安装包使用开发签名；正式商店签名、真机、多厂商通知策略、公网 TLS、反向代理和大文件内存压力未在本次验收中覆盖。
