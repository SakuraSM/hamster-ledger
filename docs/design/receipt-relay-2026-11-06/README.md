# 仓鼠记账：凭证接力全页面视觉稿

这套视觉稿沿用用户选定的第二轮第3张方向，并按“优先着重资产管理能力”的要求，先完成资产主流程，再展开其余页面。

交付覆盖140个页面与关键状态，包含138张手机稿、131张桌面稿，另有14张长页续图及59张看板。逐页PNG、离线浏览索引与验证记录均保存在本目录。它们是设计与状态演示，示例数据不会写入真实账本。当前正式产品入口仍沿用原界面。

## 从资产管理开始看

打开 [离线图集](index.html)，默认显示资产总览；切换“手机端 / 桌面端”可浏览同一流程在不同屏幕中的布局。

- [资产主流程看板](boards/assets-main.png)：总览、账户依据、负债、还款、校准差额和净资产变化。
- [历史与估值边界看板](boards/assets-history.png)：基准历史、原始账单、未关联记录、外币、缺少基准和归档。
- [账户类型与特殊余额看板](boards/assets-types.png)：账户类型、资产/负债表单、信用卡预存、投资估值和汇率。

资产页把净资产拆为总资产与总负债。手机端按账户类型收拢网络钱包，桌面端直接展开独立账户。账户详情把余额拆为明确基准与之后的已确认变动，提供原始账单、历史、校准和转账入口。

现金样例串起完整的追溯与校准流程，信用卡样例串起还款流程。其他账户尚未展开的历史、编辑或校准分支会提示“静态示意”并保留当前对象，不会跳到现金样例。分类与账本归档分别使用对应对象的确认说明。图集索引可直接打开所有独立稿件。

重点流程包括：

1. **追溯余额**：资产 → 现金 → 余额变化 / 原始账单 → 基准历史。
2. **核对差额**：现金 → 核对实际余额 → 20元差额预览 → 新基准结果；旧历史保留，不新增消费。
3. **负债还款**：信用卡 → 还款500元 → 两端余额变化；资产与负债同时减少，净资产不变。
4. **处理不完整数据**：未关联账户、缺少历史基准或汇率均明确标出，提供补充入口，不以0元或1:1汇率替代。
5. **归档与特殊账户**：归档改变当前统计范围但保留历史状态；信用卡负值按预存表达，投资与外币保留手动估值来源。

## 视觉与交互规则

- 纸白底色、石墨文字、橄榄辅助色与杏橙主操作。票据形态用于凭证阅读，资产与列表页面保持连续平面，避免所有信息都塞进卡片。
- 金额是主要视觉锚点，状态与来源紧随其后。错误、待确认、只读等状态同时有文字说明。
- 手机主导航为“待处理 / 账单 / 资产”；工具与账号从顶部和工具页进入。资产成为直接可达的主入口。
- 桌面把列表、凭证工作区与上下文分开。登录、注册和解锁使用独立入口，不展示已登录侧栏或财务摘要。
- 手势用于浏览与展开；入账、合并、删除、清空等操作保留明确按钮与确认反馈。
- 相比选定概念稿，最终稿加深了小字与状态色，并用深色按钮文字提高杏橙背景上的对比度。底部“我的”调整为“资产”，对应后续的资产优先要求。

## 虚构金额的核对依据

以下均为合成设计样例，不代表用户真实账户或市场报价。

| 项目       | 金额与口径                                                  |
| ---------- | ----------------------------------------------------------- |
| 当前资产   | 工资卡26,000 + 现金3,200 + 支付宝1,234 + 微信486 = 30,920元 |
| 当前负债   | 信用卡2,500元                                               |
| 当前净资产 | 30,920 − 2,500 = 28,420元                                   |
| 本期变化   | 期初21,206.40 + 收入8,500 − 支出1,286.40 = 28,420元         |
| 还款500元  | 工资卡25,500，信用卡负债2,000，净资产仍28,420元             |
| 现金校准   | 3,200 → 3,180，差额−20；净资产28,400，不新增支出账单        |
| 现金归档   | 当前净资产变为25,220；11月5日历史净资产仍28,476元           |
| 外币示例   | US$200 × 手动参考7.10 = ¥1,420；该参考值不代表市场报价      |

余额基准使用2026-10-31 23:59，以支持11月的期初比较。原币、投资、借贷、报销与特殊状态可使用独立示例对象，不能把所有状态稿直接相加。

完整仓库中的[资产证据测试](../../../tests/design-assets-evidence.test.ts)调用现有账务核心核对账户投影、月度变化、还款、校准与归档历史，避免视觉稿中的金额关系自相矛盾。

## 范围与格式

页面索引覆盖设计时的Web主路由、Android主入口、16个Android工具入口及其表单、弹层和关键状态；不是把组件文件数量当作页面数量。正式界面新增“待处理”入口，Android 主导航收敛为待处理、账单、资产，总览和报表仍可从工具进入。平台专属界面只导出相应版本。

- 手机：390×844逻辑画布，PNG为780×1688。
- 桌面：1440×1024 PNG。
- 长页：保留首屏和 `--continued` 续图；固定操作区继续可见。
- [页面定义与来源](catalog.json)、[覆盖核对](coverage-verification.json)、[导出检查](capture-audit.json)、[可访问性检查](accessibility-audit.json)。
- [选定方向与资产来源](ASSETS.md)、[设计校对记录](design-qa.md)。

资产类型、离线只读、模型权限和密码用途均沿用当前产品边界。视觉稿没有新增银行实时查询、实时行情、自动收益预测或真正的令牌/邀请。真实模型质量、终端通知送达与生产环境协作不属于本次视觉交付的验收结论。

## 本地复验

在仓库根目录使用Node22或24与npm：

```sh
npm run dev --workspace @hamster-ledger/web -- --host 127.0.0.1 --port 5196 --strictPort
```

浏览 `http://127.0.0.1:5196/design-preview.html`。纯画面参数为 `?raw=1&scene=assets&mode=mobile`；桌面将mode改为desktop。预览中的按钮可切换关联稿件，字段只用于演示，不提交真实数据。

```sh
node scripts/verify-design-pack.mjs
node scripts/build-design-gallery.mjs
npm run check
```

离线图集可直接打开，无需启动服务。浏览器检查通过只说明已列出的画布、状态和组件，没有替代真实Android原生实现或业务验收。
