# 仓鼠记账双端交互与布局规范

改资产、账单、预算或共用控件时，先选一条用户路径，再确定需要复测的最小布局单元。例如从资产名单进入账户，检查对象包括账户名、币种、余额、小箭头，以及从详情返回后的列表位置。沿用项目的字体、图标和颜色。

| 检查对象         | 项目验收条件                                                                                                             | 复测方法                                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| 页面宽度         | Web 在 320、360、390、768 和 1440 CSS px 下可完成主要操作。表单按空间换行。二维报表可以在自己的区域内横滚。              | 比较根元素的 scrollWidth 和 clientWidth；逐项查看标签右缘、复选框、必填标记、错误提示与保存按钮。            |
| 金额与长名称     | 金额使用等宽数字，同列标题和金额右缘误差不超过 1 CSS px。负号、货币和小数位完整可见。名称可折行，进入详情可以读到全名。  | 在测试账本输入长中文名、中英混排名及八位整数加两位小数。检查金额与名称的边界，切换隐藏金额，检查摘要和各行。 |
| 触控区域         | Android 独立操作至少 48 × 48 dp。Web 桌面独立按钮以 24 × 24 CSS px 为下限，触屏主要操作以 44 × 44 为目标。图标可以更小。 | 量可点击节点的边界。原生像素除以显示密度，先将节点完整滚入视口，再测量及点按边缘。                           |
| 选中与状态       | 筛选、导航、收支及资产分析口径有可见的选中标识，并向辅助技术暴露状态。无估值、零余额和金额隐藏使用不同文案。             | 切换两次，检查读屏名称、选中态、标题和数据范围是否一同变化。                                                 |
| 弹层、键盘与返回 | 弹层打开时焦点进入内容；键盘可以到达主操作。关闭后回到触发处。底部导航、安全区与软键盘不遮住最后一个可操作项。           | Web 用 Tab、Shift+Tab 和 Escape；Android 用系统返回。打开记账、编辑或分析弹层，在输入与收起键盘后滚到底部。  |
| 字号与可读性     | 正文和辅助说明保留清楚的层次。错误紧邻出错字段。扩大字号时内容可折行，保存、关闭及完整金额仍可达。                       | 在常规字号和放大字号下检查标签、币种、日期、长按钮、图例；分别检查浅色与夜间主题。                           |

Web 的尺寸和重排基准参考 [WCAG 2.2 指针目标](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)和[内容重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。Android 复用项目的 MIN_TOUCH_TARGET，依据为 [Android 无障碍触控指南](https://developer.android.com/guide/topics/ui/accessibility/apps)。

## 如何记录一次走查

在本地预览与隔离模拟器使用空账本和虚构数据。记录版本、窗口或设备尺寸、操作路径、问题出现的状态、修复前后测量值和截图。通用入口适合做宽度扫描，涉及金额、保存和返回的路径需要实际操作。把未覆盖的键盘、读屏、主题或物理设备单独列出。

本轮实测见[布局走查记录](design/layout-audit/README.md)。
