# 可靠性与日常流程优化

本次基于 `v0.4.0`，工作分支为 `feat/reliability-workflows`。版本号未提升；这些结果不代表已经发布或部署。

## 数据与安全

- Android 认证操作绑定服务器、会话和请求代次，串行持久化凭据，过期响应不能替换当前账号。
- 批量业务变更改用索引，批末统一校验；限制累计计算量。服务端附件上传统一按用户锁定配额。
- 私网模型请求须同时获得部署者的精确 origin 白名单授权和用户配置许可。旧配置同样受新策略约束。
- 保存前验证收支、账户余额及历史差额的安全整数范围。极端金额即使相互抵消，也可能因中间计算不安全而被拒绝。
- 页面计算异常时保留账本，提供重试及工具/备份入口。外币估值仍取决于汇率数据；此入口不自动修改账本。

## 使用流程

| 场景     | 本次行为                                                                                                         |
| -------- | ---------------------------------------------------------------------------------------------------------------- |
| 工具页   | Web 首次进入时挂载对应面板；Android 按记录、计划、账本和偏好分组。显示数据保存位置、同步方式与离线编辑边界       |
| 待处理   | 汇总重复/待确认流水和 AI 草稿入口；Android 增加支付通知收件箱入口。收件箱数量须打开本机模块查询，不展示猜测值    |
| 简单记账 | 可选择保存后继续录入；按已确认的简单交易生成常用快捷填入项。复杂交易继续使用原编辑器                             |
| 导入     | 可保存同来源、同表头的字段映射；复用后仍要求确认。模板不保存默认付款账户。错误导出包含文件指纹、错误原因和原始行 |
| 筛选     | 两端支持命名方案、待报销/未关联账户快捷方案及返回位置。方案保存在本设备，不上传或随归档迁移                      |
| 资产     | 新归档/恢复操作记录时间；历史净资产按当时状态计算。旧归档没有可靠时间，继续沿用原排除口径，不回填推测日期        |
| 预算     | 显示本期预算、上期结转、可用预算和实际支出的组成；仍以既有账期规则计算                                           |
| 长列表   | AI 草稿、通知及 Web 回收站初始显示 30 条，按需增加；主流水沿用分页或原生虚拟列表                                 |
| 提醒     | Android 可查询系统通知权限、每日任务与通知通道。支付通知页解释授权、连接及未采集原因                             |

常用交易快捷填入来自历史交易，不是单独维护的命名模板库。Web 工具面板首次进入时才挂载，同一工具页内切换会保留已打开表单的临时内容；离开工具页或切换账本前仍应完成当前操作。

## 同步规则

两端共用 `snapshotSyncAction`，以最后一次成功同步的指纹和版本号为基准：

| 本机变化 | 云端变化 | 行为                                                           |
| -------- | -------- | -------------------------------------------------------------- |
| 无       | 无       | 保持当前账本                                                   |
| 有       | 无       | 按预期版本上传                                                 |
| 无       | 有       | 请求期间本机未编辑、未切换账本或账号时自动下载                 |
| 有       | 有       | 暂停自动同步、展示云端预览；恢复到新账本后核对，保留原本机账本 |

Android 同步挂载在应用层，前台轮询并在恢复前台时检查；后台不轮询。Web 保持页面可见时同步。联网家庭账本继续使用业务操作与权限接口，不走整本快照同步。

## 备份格式与取消

完整归档支持明文和可选密码加密，均先预览再恢复为新账本。旧 JSON 及旧明文 `.hamster` 仍可读取。

加密格式为 `hamster-ledger-encrypted / version 1`：PBKDF2-SHA256，310,000 次迭代、16 字节随机盐；AES-256-GCM，12 字节随机 IV、16 字节认证标签。Web 使用 Web Crypto；Android 使用 Expo 原生 AES 和 [noble-hashes PBKDF2](https://github.com/paulmillr/noble-hashes)。解析只接受固定参数，避免文件指定任意高成本 KDF。密码不落盘；错误密码或篡改文件不能进入恢复预览。

“最近生成备份”只证明应用生成过导出文件，不能证明用户已经在下载目录或分享目标中保存。取消在当前文件或加密步骤结束后生效；恢复在新账本写入前检查取消，并清理已暂存附件。最后提交完成后不再撤回已创建的新账本。原账本不被覆盖。

归档不包含账号、Token、模型主密钥、筛选方案或未确认支付通知。服务端恢复仍需 PostgreSQL 备份与原模型主密钥，见[容器运维](container-operations.md)。保存历史归档状态需要本次客户端；旧客户端不了解新增字段，混用旧客户端编辑可能丢失这些历史字段。

## 验证范围

自动化覆盖认证竞态、附件并发配额、批量变更、金额越界、同步冲突/过期响应、保存筛选、字段模板、取消恢复及加密归档。跨端加密互通单测执行真实 PBKDF2 和独立的 AES 实现，Expo AES 绑定由 Node 实现替代。另在 Android API 36 模拟器中验证了实际原生解密，成功读取 Web 导出的 124 笔账单、4 个账户归档。原生验证发现 Expo 的密文编码参数与声明不一致，已改用字节接口并显式 Base64 编码，单测同步覆盖字节返回值。修复后，Android 实际导出的加密备份也在 Web 解密成功，预览为 2 笔账单、1 个账户、1 张凭证；附件通过哈希校验，随后恢复为新 Web 账本，支出仍为 27.50 元。

Ego 浏览器使用独立端口与虚构数据验证了工具切换、面板临时输入保留、筛选保存与返回恢复、连续记账、密码加密导出、解密预览及新账本恢复。桌面和 390×844 视口均已检查；移动视口无横向溢出。工具主页与备份页的 axe WCAG A/AA 检查均为 0 项违规。截图见 `docs/images/modern/web-tools-grouped.png` 和 `web-encrypted-backup.png`。

AI 评估脚本 `npm run evaluate:ai` 使用 8 个合成文本样本，分别记录金额、账户、日期、非法金额拦截、重复草稿和默认人工确认。结果见[评估数据](evidence/reliability-2026-10-19/ai-rules.json)。没有调用真实模型或 OCR，不应把这些结果当作模型准确率。

性能脚本 `npm run benchmark:ledger` 使用 1,000、5,000、14,999 笔合成账单；最大规模加表头共 15,000 行。每个规模先预热一次，再记录 5 次的中位数和最大值。结果见[性能数据](evidence/reliability-2026-10-19/performance.json)。测量仅包括进程内解析、汇总、无附件归档和恢复，不包括 UI、网络、加密或附件传输；它是后续比较基线，不代表手机耗时或优化百分比。

没有连接 Android 真机；真实支付模板、锁屏、设备重启和厂商省电限制仍待验收。当前没有真实模型识别或生产环境协作验收。

## 依赖审计补充

本次新增 `@noble/hashes 2.4.0` 用于 Android 密钥派生；`source-map-js` 从 1.2.1 更新到已修复版本 1.2.2。锁文件未批量升级 Expo 或 React Native。

`npm audit --omit=dev` 更新后仍报告 25 个依赖节点告警（17 high、8 moderate），集中在 3 条根因公告：`braces` 经 micromatch、`node-forge` 经 Expo CLI/签名工具、`uuid 7` 经 xcode。它们属于构建/开发工具依赖路径；本轮未证明应用业务入口可触达，也未宣称依赖零漏洞。查询时 braces 与 node-forge 的最新版本仍在公告范围内；uuid 的修复涉及跨主版本，不采用审计工具建议的大跨度 Expo 降级。

这部分与已复现并修复的五项源码问题分开记录，不能用源码回归通过替代依赖公告处置。

附加 DFA 风格扫描启用仓库日常 ESLint 之外的 `max-params`、`no-magic-numbers` 等规则，仍有 63 条告警，严格零告警模式未通过；修改文件均已控制在 300 行以内。仓库规定的类型、ESLint、边界和格式检查单独执行。剩余风格项需按所在模块逐步命名常量、收拢参数，不在本轮批量改写无关旧代码。若需复验页面无障碍，可运行 DFA 的 `scripts/a11y-audit.sh <本地页面URL>`；本轮实际浏览器检查使用 Ego 注入 axe。

最终验证记录：`npm run check` 完整通过，包含 314 项 Vitest、67 项 PostgreSQL 和 4 项 Sites 测试，另含依赖兼容、类型、ESLint、格式和边界检查。一次与 Android 构建并行的全套运行中，既有字段映射 UI 测试超过 5 秒；停止构建竞争后完整重跑通过，未放宽超时或削弱断言。Android API 36 模拟器覆盖安装保留了原测试账本；真机验收仍不在本次已完成范围内。
