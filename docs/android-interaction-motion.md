# Android 交互过渡与重复渲染优化

本次调整让工具页进入和返回具备连续过渡，减少切换标签时的重复渲染。普通收支页面、账单与报表仍保持原状态，不通过卸载页面来换取动画效果。

## 改动

- 主题只在主题选择或减少动态效果设置变化时重建，避免普通导航状态触发 Paper 全局主题刷新。
- 总览、报表及账单行使用默认浅比较复用。账本内容、月份、回调或主题确实变化时仍更新，账单金额和状态不会被冻结。
- 工具页具有独立的不透明背景，进入使用 220ms 淡入和 16dp 位移，返回时主页面以 160ms 完成 4dp 位移复位，始终保持可见，避免空白闪帧。动画使用原生驱动，不占用交互队列；插值节点与动画值只创建一次，同页数据刷新不会重启动画。
- 工具页关闭仍立即卸载其业务组件，不能为了退出动画延迟未确认消息等业务的清理。原有报表日期、选点、搜索状态保留。
- 标签切换继续沿用 Paper 原有的原生动画，统一强调型缓动。原生表单弹窗继续使用系统过渡。
- 使用内部主题提供器保留明确的 `animation.scale`，避免 Paper 默认值覆盖应用的减少动态效果设置。导航、工具页与表单都遵循同一偏好。

## 测试与性能边界

新增七项 React 行为测试，覆盖主题引用复用、主题变更、减少动态效果传递、同页刷新不中断动画、关闭时立即清理、底层状态保留及账单行复用。账单行测试在旧实现失败，父层更新会渲染两次；新实现对同一记录只渲染一次，记录变更时继续正常更新。完整检查包含 303 项测试。

在 API 36 ARM64 模拟器上，分别覆盖安装旧包和新包，各预热五个标签后执行三轮固定顺序切换，每轮 25 次点击、点击间隔 250ms。测量期间没有并行运行构建或测试。旧包为上一版金额语义调整 APK；原生动画测量使用 `dumpsys gfxinfo ... framestats`。原始计数见 [verification.json](evidence/android-motion-2026-10-12/verification.json)。

这组常规标签切换的帧耗时没有观察到稳定提升，不能据此宣称整体帧率改善。本次可确定的结果是减少重复渲染、补齐工具页过渡及修复减少动态效果传递。模拟器统计不代表 OPPO 真机上的滚动性能、120Hz 流畅度或用户体感。

本次只调整展示和动画生命周期，不修改账本模型、金额算法、存储、同步或通知采集规则。
